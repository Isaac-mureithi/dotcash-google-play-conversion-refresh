# DotCash Google Play Conversion Refresh

**Role:** Assistant Product Manager  
**Product:** DotCash Credit  
**Deliverable:** Google Play Store screenshot refresh  
**Timeline:** First 2 weeks in role  
**Status:** Accepted

## Overview

One of my first deliverables after joining DotCash as an Assistant Product Manager was to improve the Google Play Store screenshots for the DotCash lending app.

The existing screenshots communicated the main features, but they read more like a collection of product screens than a clear story for someone discovering the app for the first time.

I approached the task from both a product and design perspective. Instead of simply redesigning the existing screenshots, I looked at what a prospective borrower needed to understand and how the six screens could communicate that journey in sequence.

The final set was reviewed, revised based on feedback, and accepted.

---

## The Brief

The task was to create a new set of Google Play screenshots that better communicated the DotCash product and its key benefits.

The existing set included messaging around:

- Loan amount
- Application
- M-Pesa payment
- Repayment and loan extension
- User centre / support

The opportunity was to make the set more cohesive and clearer at a glance.

## My Interpretation

I treated the screenshot set as a product communication problem rather than six separate marketing graphics.

A user discovering the app should be able to understand, in a few seconds:

- How much they can borrow
- How they get started
- What happens when they apply
- How they receive the money
- How they repay
- Whether they need collateral

This led to a simple narrative:

**Access → Get Started → Apply → Receive → Repay → Reassurance**

The objective was to give every screenshot a distinct job within that story.

---

## Exploration

The first challenge was deciding what each screen should communicate.

I mapped the existing product screens and available assets against the customer journey, then explored how the UI, copy, people, device mockups, and supporting visual elements could work together.

The visual direction moved away from simply placing screenshots inside a phone and towards showing the product experience more clearly.

The main visual elements became:

- Real DotCash app UI
- Phone mockups
- Human imagery
- Elevated UI elements
- M-Pesa visual cues
- Short, benefit-led headlines
- Consistent device perspective and styling

I kept the actual product UI as the source of truth rather than recreating or redesigning the screens for the marketing assets.

---

## Product Narrative

The final six screens were structured around the borrowing journey.

### 01. Loan Amount

**Get Up To KSH 80,000**

The first screen establishes the primary proposition and immediately communicates the maximum loan amount.

### 02. Getting Started

**Get Started In 3 Simple Steps**

This screen communicates the simplicity of getting a profile ready before applying.

This distinction became important later because "profile approval" and "loan approval" could easily sound like the same thing.

### 03. Loan Application

**Apply For Yours And Get It Fast**

This screen represents the actual loan application and its outcome.

The messaging was kept separate from Screen 2 so that the user journey is clearer:

**Get started → Apply → Get approved**

### 04. M-Pesa

**Receive Money To Your M-Pesa**

The visual communicates the next step after approval: receiving the funds directly through M-Pesa.

The composition combines the successful loan state, M-Pesa branding, and transaction messaging to make the outcome immediately understandable.

### 05. Repayment & Extension

**Easy Repayment And Extension**

This moves the story beyond receiving the loan and shows the available repayment and extension options.

The visual focuses attention on the repayment amount, repayment action, extension option, and available payment methods.

### 06. No Collateral

**No Collateral Needed**

The final screen communicates an important barrier-reduction proposition: the customer does not need to provide an asset as collateral.

The visual uses a simple flow to connect borrowing, receiving money, and repaying the loan.

## Visual Execution

The six screenshots were designed as one visual system.

I established a consistent treatment for:

- Phone size and perspective
- Human imagery
- Brand colours
- Typography
- UI presentation
- Elevated visual elements
- Spacing
- Headline hierarchy

For some screens, UI elements were taken beyond the phone to create a stronger visual connection between the product interface and the message being communicated.

For example, the three application steps were visualised as separate elevated layers coming out of the phone. The M-Pesa screen used elevated M-Pesa and notification elements to reinforce the money-transfer story. The repayment screen used elevated repayment and extension actions to draw attention to the two key options.

The goal was not to decorate the UI, but to make the product story easier to understand visually.

---

## Copy & Hierarchy

One of the areas that required the most thought was the relationship between the headline and the product UI.

The copy needed to be short enough to work within the Google Play screenshot format while still communicating a clear benefit.

The general structure became:

**Benefit-led headline**  
Short supporting context where needed  
**Product UI / visual proof**

A key example was the distinction between Screens 2 and 3.

Initially, both screens risked communicating "approval", which could make the journey feel repetitive.

The messaging was refined to distinguish:

**Profile readiness → Loan application → Loan approval**

This gave each screen a clearer role.

---

## Feedback & Iteration

The first version went through internal review.

Feedback led to several refinements across the set, including:

- Adjusting the messaging hierarchy
- Separating profile approval from loan approval
- Refining the relationship between headlines and UI
- Correcting the repayment amount to Ksh 5,000
- Aligning the perspective of elevated UI elements
- Refining the M-Pesa notification and branding
- Adjusting spacing and visual balance
- Refining the no-collateral visual

The work went through these iterations before the final six-screen set was accepted.
